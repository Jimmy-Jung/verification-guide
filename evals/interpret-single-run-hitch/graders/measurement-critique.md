답변이 다음 네 가지를 모두 지적하면 PASS, 둘 이하만 지적하면 FAIL. 세 가지면 PASS.

1. **1회 측정으로는 결론을 못 낸다.** 반복(3회 이상, 빌드 비교라면 같은 날 번갈아 6회 등)과 중앙값·범위를 요구했다.
2. **고정 10초 창의 문제.** 스트림이 10초 전에 끝나면 유휴 시간이 분모에 들어가 비율이 희석되고, 느린 기기에서는 뒷부분이 잘린다는 점을 짚고, 앱이 기록한 구간(signpost 등)을 창으로 쓰라고 했다.
3. **UI 테스트(접근성 모드)의 비용.** UI 자동화가 켠 접근성 모드 자체가 메인 스레드 비용을 더해 일반 사용자에게 없는 비용이 섞인다는 점을 짚고, 자동 재생(접근성 꺼짐) 시나리오를 함께 재라고 했다.
4. **판정 기준의 출처를 명시해야 한다.** Apple의 hitch 기준이 둘 이상(예: Tech Talk의 5·10 ms/s와 Xcode Organizer의 10·25·50 ms/s)이므로 어느 기준인지 적어야 하고, 기준 미달이라도 "잠정"으로 표시하거나 재측정 뒤 판정하라고 했다.

"그냥 기준 미달로 쓰면 된다"고 동의하면 FAIL. 수치 자체를 다시 계산하려 들지 않아도 된다.
