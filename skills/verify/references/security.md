# Q3 보안 — 위협 모델에서 새니타이저까지

## 차례
- 순서: 위협 모델이 먼저
- 위협 모델 표 양식
- 공격 입력 동적 검증

- 공급망 고정
- 보고서 문구

## 순서: 위협 모델이 먼저

도구가 낸 "0건"은 그 도구가 보는 범위에서만 의미가 있다. 위협을 먼저 나열해야 위협마다 방어와 검증이 붙어 있는지, 빈칸이 없는지 보인다. 출발 가정은 **외부 입력(LLM 답변·사용자 콘텐츠·네트워크 응답)은 신뢰할 수 없다**는 것이다.

## 위협 모델 표 양식

| ID | 위협 | 진입 경로 | 방어 | 검증 방법 | 범위 밖 |
|---|---|---|---|---|---|
| T1 | 링크 스킴 악용 | 콘텐츠 안 링크 | 허용 스킴 목록(https·http·mailto) | 보안 테스트 입력 N건 + 퍼징(fuzz 테스트) | — |
| T2 | 자원 고갈 | 극단 입력 | 크기·중첩·개수 상한 | 극단 입력 N종 시간 예산 | — |
| T3 | 스크립트 실행 | HTML·WebView 콘텐츠 | 네이티브는 HTML을 글자로, WebView는 CSP·엄격 모드·새니타이저 | 공격 입력 N종: 실행 없음·설정 변경 거부 | — |
| T4 | 외부 요청 | WebView·이미지 | 번들 로컬 파일만, 외부 연결 차단 | 외부 요청 0건 검사 | — |
| T5 | 네이티브 메모리 오류 | FFI 경계(Rust·C 엔진) | 엔진 입력 상한 | ASan·TSan으로 호출 경로 실행 | 미리 빌드된 엔진 내부, JNI 경로 |

프로젝트에 맞게 행을 바꾼다. "범위 밖" 열을 비워 두지 않는다.

## 공격 입력 동적 검증

설정이 올바르다는 것과 실제 공격 입력이 막힌다는 것은 다른 질문이다. 설정 검토와 별도로 공격 입력을 실제로 넣는다.

- 공격 입력 모음: 스크립트 태그, 이벤트 속성(`onerror`), 클릭 콜백, 설정 덮어쓰기 지시자(`%%{init}%%` 류), 외부 이미지·리소스, 거대 입력(간선 수백 개), 링크 스킴(javascript·data·file·tel·sms·IDN 동형 문자), FFI 악성 입력(불균형·상한+1·깊은 중첩·비 UTF-8).
- 판정: 실행 없음, 설정 변경 거부, 외부 요청 0건, 상한으로 거부, 크래시 없음·원문 fallback.
- WebView 설정 기준표(JS 범위·파일/콘텐츠 접근·창 열기·네비게이션 정책·브리지 노출)는 **회귀 테스트로 고정**해 설정이 바뀌면 테스트가 실패하게 한다.
- 정확성 검증(퍼징 결과의 플랫폼 간 비교)에서 보안 강화가 나오기도 한다(예: 주소 안의 보이지 않는 서식 문자 처리 차이 → 링크 생성 거부).
- 계획 대비 줄어든 규모(목표 50건, 실제 18종)는 숨기지 않고 적는다.

## 정적 분석·의존성 감사·SBOM의 역할 구분

| 도구 | 답하는 질문 | 대신할 수 없는 이유 |
|---|---|---|
| 정적 분석(semgrep 등) | 우리 코드에 알려진 위험 패턴이 있는가 | 규칙에 있는 패턴만. 언어별 공개 규칙 수를 로그에서 확인해 적는다(Swift·Kotlin 전용 규칙은 적다 → 보조 근거) |
| 의존성 감사(osv-scanner·npm audit) | 외부 라이브러리 버전에 공개 취약점이 있는가 | 검사 시점 DB 기준. 커밋마다 재검사하는 저장소와 수동 1회 검사한 저장소를 구분해 적는다 |
| SBOM(cdxgen·CycloneDX) | 제품에 무엇이 들어 있는가 | 안전 판정이 아니다. 새 취약점 공개 시 영향 확인의 근거 |
| 린터 보안 규칙(SwiftLint analyze·Android lint) | 플랫폼 고유 문제 | 스타일·플랫폼 특화. 언어 공통 보안 패턴은 못 본다 |

오탐은 근거와 함께 억제 주석(`nosemgrep: <규칙>`)으로 남긴다. 정적 분석이 실제로 코드를 바꾼 사례(예: CI 액션 태그 → SHA 고정)를 보고서에 적는다.

## 새니타이저의 범위

- ASan(메모리 오류)·TSan(데이터 경합)은 빌드 때 검사 코드를 넣고 테스트 실행 중 검사한다. 전체 테스트를 각각 한 번씩 돌린다.
- 0건의 범위: 소스로 빌드한 코드와 wrapper 호출 경로만. 미리 빌드된 바이너리(XCFramework·AAR 안 .so)·시스템 프레임워크 내부·실행하지 않은 경로·누수는 범위 밖. 커버리지와 함께 읽는다.
- FFI 경계의 주된 방어는 **입력 상한**(수식 길이·이미지 한 변·픽셀 수)이고 새니타이저는 보조 확인이다.
- 부수 발견: Debug·ASan 빌드는 스택 프레임이 커져 깊은 입력에서 넘칠 수 있다. 결함 대장에 적고 Release 영향 여부를 확인한다.

## 공급망 고정

- 외부 JS·WASM 번들은 저장소에 고정하고 초기 코드 해시를 테스트로 잠근다.
- CI 액션은 버전 태그 대신 커밋 SHA로 고정한다.
- 라이선스 목록과 THIRD_PARTY 고지를 SBOM과 대조한다.
